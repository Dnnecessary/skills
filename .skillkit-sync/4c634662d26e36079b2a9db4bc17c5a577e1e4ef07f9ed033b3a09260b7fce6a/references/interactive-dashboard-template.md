# 作者内容方法论交互可视化看板模板

适用场景：执行 `author-methodology-analysis` 时默认使用。只有用户明确要求不生成 HTML，或调用参数 `generate_html=false` 时跳过。

## 看板定位

看板应回答：**这个作者有什么值得学习，我应该怎么学？**

不是回答：

- 哪篇文章机会分最高；
- 哪些样本可筛选；
- 单篇文章明细有哪些；
- 文章列表如何排序。

核心原则：所有图表和交互都必须服务于“作者内容方法论”的理解、复用和迁移。

## 推荐文件

- 输出文件：`<output_dir>/<博主>-方法论看板.html`
- 单文件 HTML，允许使用 CDN 图表库；若运行环境无法联网，应提供纯 CSS/SVG 降级图表。

## 标准信息架构

看板默认采用长页研究报告结构，一级维度固定对应：

1. **00 一页看懂**：用一句话和三条核心判断快速说明作者是谁、如何写、值得学什么。
2. **01 定位与价值**：作者定位、目标读者、可信度来源，以及学习者是否具备可迁移条件。
3. **02 内容地图**：主要主题、内容类型及不同内容承担的作用。
4. **03 选题方法**：选题来源、切入角度、优先级和判断标准。
5. **04 文章写法**：标题方法、开头任务、正文论证路径、结尾方法和具体练习。
6. **05 观点与证据**：结论如何形成，使用了哪些实测、案例、数据、引用和边界说明。
7. **06 语言风格**：表达节奏、句式、术语密度、观点强度和辨识度。
8. **07 值得学习**：把作者优势翻译成学习者可以训练的具体能力。
9. **08 运营增长**：学习内容增长方法、栏目设计、内容迭代、竞品观察和适合自己的更新节奏。
10. **09 学习与迁移**：提供练习动作、学习顺序、迁移标准和不能照搬的条件。
页面底部增加简短的**来源说明与免责声明**，不作为独立分析章节。

顶部导航使用上述十个维度。整个看板默认站在学习者视角，每个章节回答：**他怎么做、为什么有效、我值得学什么、我具体怎么练、哪些不能照搬**。

### 运营增长模块

运营增长必须建立在内容方法论之后，不能只罗列通用运营技巧。推荐包含：

- **涨粉策略**：区分入口内容、信任内容、工具内容和定位内容，并说明各自承担的内容任务。
- **栏目矩阵**：说明每个固定栏目的目标、频率、内容形态和预期读者动作。
- **分发动作**：分别给出发布前、发布后 24 小时和发布后 7 天的执行动作。
- **竞品研究**：对比定位、读者、主题、栏目、更新节奏、标题封面、证据深度、互动问题和转化路径。
- **内容迭代学习**：解释如何从读者问题、实测变化和新案例中发展下一篇内容或长期栏目。
- **更新节奏怎么学**：用发布日、星期分布、同日多篇和间隔中位数观察作者如何保持输出，再根据学习者的时间、证据积累和创作熟练度给出可持续节奏；不得要求机械照搬日更或高频发布。

看板不分析平台后台的阅读、分享、点赞、收藏、关注或转化数据，也不设置这些指标的“待补”区域。没有竞品样本时，只提供研究框架和执行建议，不虚构竞品结论。

### 必须包含的学习模块

- **标题方法拆解**：保留整体维度统计，但面向学习者展示代表标题的公式、有效原因、仿写方法和适用条件，避免逐篇分数堆叠。
- **文章结构示范**：把节奏解释为开头任务、中段任务和结尾任务，并为每一步提供可执行练习，避免抽象柱状图。
- **结尾方法学习**：解释作者如何通过提问、建议或预告推动下一步，并提供学习者可使用的写法。
- **内容方向学习**：呈现作者已覆盖的主题与可启发学习者建立差异的方向，不要求作者补齐。
- **竞品选题雷达**：使用公开搜索可见的同行标题样本，对比选题类型；展示来源链接和样本边界。

### 数据使用规则

- 数据范围限定为文章正文、公开元数据和可回溯的人工标注。
- 不得把发布时间、正文 CTA 或模式匹配次数命名为传播效果或转化效果。
- 正文中的行动引导可以作为写作结构观察，但不能作为运营效果指标。
- 归因分析只能描述样本中的关联，不得把少量样本关联写成因果。

### 2. 方法论模块雷达

推荐模块：

- 选题系统
- 分析框架
- 判断标准
- 表达模板
- 案例库
- 金句风格
- 内容机会 / 资产化能力

若使用分值，每个分值必须来自公开且可复算的信号，例如：

- 主题稳定性
- 证据充分度
- 结构可复用度
- 案例复用度
- 判断标准清晰度
- 表达模板稳定性

无法定义可靠公式时使用“证据充分 / 部分充分 / 证据不足”等定性等级。不要展示无公式的成熟度指数，也不要称为“机会分”。

### 3. 方法论漏斗

推荐链路：

1. 事件触发：热点、新品、争议、趋势、读者痛点。
2. 能力拆解：变量、机制、场景、对象、成本、风险。
3. 真实体验 / 证据验证：案例、测试、引用、对比、数据。
4. 立场判断：适合谁、不适合谁、为什么值得关注。
5. 内容资产化：榜单、雷达、清单、系列、案例库、SOP。

### 4. Methodology Summary / 方法论深潜

交互结构：

- 左侧：方法论模块按钮 / Tab。
- 右侧：模块详情联动展示。

每个模块至少包含：

- 核心判断：一句话说明该模块如何工作。
- 拆解逻辑：3-5 条方法论规则。
- 证据信号：来自样本的可观察依据。
- 可复用动作：下一次写作/选题可直接执行的动作。
- 代表文章证据：标题或片段，注意不是样本明细表。

### 方法论证据中枢

确定性脚本生成的基础版至少提供：

1. 样本概览与来源范围
2. 高频词与文章覆盖率
3. 文章级证据表
4. 发布时间、篇幅、结构、证据、CTA 等确定性统计

当 `<博主>-分析数据.json.annotations` 已包含主题、立场、读者、金句或方法论标注时，再增加相应入口。不得为了满足固定入口数量而生成空图表。

推荐结构：

- 左侧：实际有数据的维度切换入口；移动端可横向滚动。
- 中间：当前维度的图表。
- 右侧：核心洞察 + 方法论启发 + 标签。
- 底部：证据拆解卡片，说明该维度如何支撑作者方法论。

切换逻辑：

- 基础指标直接来自脚本计算字段。
- 主观模块只读取带文章 ID 和证据的 `annotations`。
- 数据不足的模块显示限制说明或不展示。

每次切换时同步更新：

- 图表数据
- 核心洞察文本
- 方法论启发文本
- 标签 chips
- 证据拆解卡片

### 内容生产链路

把作者方法论转为 SOP，例如：

1. 发现事件或问题。
2. 判断是否进入作者核心问题域。
3. 拆解变量与场景。
4. 收集案例和证据。
5. 给出清晰立场。
6. 用表达模板降低理解成本。
7. 沉淀为系列、清单、案例库或下一篇选题。

### 方法论关系矩阵

展示模块之间的互相支撑关系，例如：

| 关系 | 含义 |
|---|---|
| 选题系统 × 判断标准 | 选题决定写什么，判断标准决定为什么值得写。 |
| 分析框架 × 表达模板 | 框架保证逻辑，模板保证可读和传播。 |
| 案例库 × 金句风格 | 案例提供可信度，金句压缩成可传播观点。 |
| 判断标准 × 内容机会 | 稳定判断口径可产品化为榜单、雷达、清单。 |

## 视觉与交互要求

- 风格：研究报告式交互可视化，而不是后台 BI / Excel 明细面板。
- 信息密度：高，但要有清晰层级。
- 图表：每个图表旁边必须有解释，不让用户自行猜测。
- 交互：Tab、点击切换、Tooltip、展开详情、卡片联动均可。
- 可读性：中文字号不宜过小；雷达图标签需清晰。
- 单页结构：严格按“一页看懂 → 作者与读者 → 内容地图 → 选题方法 → 文章写法 → 观点与证据 → 语言风格 → 读者价值 → 运营增长 → 复用指南”顺序，最后以简短页脚交代来源与免责声明。

## 明确禁止 / 避免

- 不要把文章样本明细表作为核心区域。
- 不要提供文章搜索、排序、筛选作为主交互。
- 不要默认展示单篇文章详情弹窗。
- 不要使用“机会分、传播分、综合分”等不透明单篇文章评分。
- 不要把详细分析维度分散堆叠成大量独立图表；优先合并为“方法论证据中枢”。
- 不要只做词频图而不解释其方法论含义。

## QA 清单

交付前检查：

- [ ] 页面是否聚焦作者内容方法论，而不是样本管理？
- [ ] 一级导航是否严格对应十个分析维度，且不包含独立的“数据与边界”章节？
- [ ] 页面底部是否有简短的来源说明与免责声明？
- [ ] 运营增长是否明确说明“我应该学习什么”和“我要怎么学”？
- [ ] 页面是否完全移除了平台后台表现指标及其“待补”区域？
- [ ] 是否所有核心模块都明确回答“我应该学习什么”和“我要怎么学”？
- [ ] 竞品标题是否有公开来源链接，并与作者自身数据分开呈现？
- [ ] 是否没有“样本明细 / 文章筛选 / 机会分”残留？
- [ ] Methodology Summary 是否足够详细，包含核心判断、拆解逻辑、证据信号、可复用动作？
- [ ] 基础统计是否来自共享数据源，主观模块是否来自可回溯 annotations？
- [ ] 图表切换是否联动说明、标签和证据卡？
- [ ] 浏览器控制台是否无 JS 错误？
- [ ] 是否做过截图/视觉 QA？

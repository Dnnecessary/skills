# 小红书爆款图文引擎

## 定位

这个 Skill 做的是**会涨粉的爆款图文**，不是单纯的排版工具。

运营优先,版面在后:先有流量策略(选题角度、封面钩子、完读率设计、互动引导),再决定用哪套视觉风格、怎么排版。每一张图都要能回答一个问题——**凭什么让人停下、看完、点赞收藏?**

如果只追求"好看"而回答不了这个问题,这套图文就还没做完。

## 适用 / 不适用

**适用：**
- 小红书 3:4 图文笔记(封面 + 内容页),从文章、脚本、截图、产品笔记、字幕或素材改编而成
- 需要兼顾"涨粉"和"美观"的轮播图内容
- **单张封面 / 单图需求**:只要一张封面或单图、不要整套轮播,也可以——只走封面相关步骤、只渲染那一个 `.poster`
- **复盘已发布的笔记**:用户拿着一篇发过的笔记和它的后台数据,问"为什么没爆 / 怎么改进"(走下面的「复盘模式」)

**不适用：**
- 公众号封面、抖音/视频号封面、或其他平台的多尺寸需求(不在本 Skill 范围)
- 纯图片编辑(抠图、滤镜、修图等,不涉及图文版面)
- 长文 PPT / 课件型多页文档

## 开工前确认一次（源素材 · 配图）

**把缺的一次性问清，不反复纠缠。**

### 源素材（核心内容）

- **用户给了素材**(文章 / 脚本 / 笔记 / 字幕 / 截图) → 以素材为准。给的是**链接**就先抓取读取(WebFetch),给的是**长文**就按 `content-planning.md` 的压缩阶梯精简,别整篇搬上图。
- **用户只给一个话题、没有素材** → 按选题性质分两路,别默认"无素材就硬编":
  - **观点 / 方法论 / 经验科普类**:可以基于常识原创内容,但**先用一两句和用户对齐核心角度与关键主张再开做**,别自顾自定调。
  - **测评 / 数据 / 新闻 / 真实经历 / 价格类**:必须有素材或可核实来源。没有就向用户要,或联网核实(见非协商项的事实核实规则)——**绝不杜撰**具体数字、价格、引用、亲身经历。
- **账号署名**:图底栏 / 正文 / 评论区要署名时,先问用户**真实的小红书账号名**;用户没给,就不放 @、只用被推广产品的品牌名,或留一个明确标注"待填"的占位——**绝不自己编一个 @账号**(见非协商项)。

### 配图

配图直接影响"像不像 AI 批量产的"，规则同样**只问一次**：

- **用户已提供图**(照片 / 截图 / 产品图) → 直接用，按 `image-handling.md` 的优先级和配方处理。真实素材永远优先,它是最不像 AI、可信度最强的来源。
- **用户没提供图** → 按选题类型判断,不要默默出纯文字:
  - **观点 / 金句 / 新闻解读 / 纯方法论干货**:排版本身能撑住,纯文字版即可,直接做。
  - **种草 / 旅行 / 美食 / 产品 / 教程 / 测评**等"图就是证据"的选题:图缺了证据层会显单薄,主动问一次:
    ```
    这篇我建议配 1-2 张图。你想怎么走？
    A 你自己有照片/截图,发我（最推荐,最不像 AI）
    B 我去图库找（Pexels / Unsplash）
    C 用 AI 生成
    D 就纯文字版式
    ```
    用户选了就按选择走（含"你看着办"),不要后续每轮再追问。
- **新闻 / 测评 / 数据类**:尤其要主动争取真实截图作证据(官方公告、后台数据、对比结果),一张真截图胜过一段描述。

## 工作流(8 步)

```
1 选题与流量判断    → operation-engine + psychology-and-arc（触发器）（蹭热点→trendjacking；涨粉→account-persona）
2 拆解内容&页面规划  → content-planning + psychology-and-arc（情绪曲线）
3 选风格&配主题     → style-system / style-presets（对齐账号视觉签名 account-persona）
4 封面专项设计      → cover-design + hook-and-title
5 复制模板渲染      → base.css + template-<style> + layout-recipes + production-workflow
6 图上文案去AI味     → copywriting-rules(+ humanizer-zh 可选)
7 截图导出&QA       → production-workflow + qa-checklist + diagnose-and-risk（风控）+ validate-cards.mjs
8 交付             → 展示图 + 正文&评论区(caption-and-comments) + 涨粉建议(account-persona) + 发布后复盘(diagnose-and-risk)
```

### 1. 选题与流量判断

读 `operation-engine.md`,先判断这个选题/素材值不值得做成图文、有没有明显的流量短板。过一遍选题自检清单,想清楚这套图文的流量漏斗(谁会点进来、为什么会看完、为什么会互动)。

如果目标是**涨粉**(而不只是单篇爆款),同时读 `account-persona.md`:确认或帮用户定下账号定位三件套(给谁看/解决什么/谁在说),并让这个选题落在账号的选题矩阵里,而不是打一枪换一个地方。

定角度时读 `psychology-and-arc.md` 的触发器谱:想清楚这套内容**最想要什么结果**(涨粉/带货/破圈),倒推该叠哪 2-3 个心理触发器(好奇缺口/损失厌恶/身份认同/谈资/共情等),落到选题角度上。守住伦理红线:放大真实价值,不编造焦虑。

如果这是**蹭热点/借势**选题,读 `trendjacking.md`:先过"值不值得蹭"四关(相关/还热/有新角度/不踩雷),抢窗口期快出,但**事实没核实绝不抢发**。

### 2. 拆解内容 & 页面规划

读 `content-planning.md`,把原始素材按压缩阶梯精简到适合图文的信息量,用页面规划模板确定每页的角色(封面/痛点/方法/案例/总结等)和总页数。

排页顺序按 `psychology-and-arc.md` 的情绪曲线设计:不要平铺信息卡,要排出一条有起伏的情绪线(钩子→低谷共鸣→转折→信息峰→情绪峰→余味结尾)。按峰终定律,把最想被记住的内容放在情绪峰(常在倒数第二页),最后一页留余味+互动。

### 3. 选风格 & 配主题

读 `style-system.md` 判断素材气质更适合哪一套风格(baokuan/magazine/ambient/minimal),用识别测试做最终确认;再读 `style-presets.md` 取出对应的 CSS token 作为主题基础。

**用户没指定风格时**:按选题类型自动选一套,并**一句话告诉用户"选了哪套、为什么",允许用户一票改**,不要默默定。跨类选题(既像知识又像观点)按这套内容的**主要流量目标**定:要广传播/种草偏 baokuan、要质感/深度偏 magazine、要态度/金句偏 minimal、要氛围/情感偏 ambient。**用户已指定风格**则直接用,不必再判断。

若是为已有账号持续产出,优先**沿用账号已定的主风格、主色、角标与署名位置**(见 `account-persona.md` 的视觉一致性),保持跨篇辨识度,不要每篇换风格。

展示字体和质感是"好不好看"的天花板:标题尽量用有辨识度的展示字体(已内置得意黑,接在 baokuan/minimal),并按 `typography-and-texture.md` 叠一层克制的质感(噪点/渐变/光晕/暗角/柔投影),别停在纯色平涂。

### 4. 封面专项设计

结合 `cover-design.md` 和 `hook-and-title.md`:先用标题公式库和封面钩子公式库写出几个候选标题/钩子,核对"标题党的度"避免踩线,再按 3 秒法则和视觉层级原则确定封面版式,过一遍封面避坑清单。

### 5. 复制模板渲染

**渲染前先确认一次**(尤其 ≥6 张):把"选定风格 + 页面规划(每页角色与核心文案) + 封面钩子方案"给用户过一眼,确认后再正式批量渲染——一张张截图很慢,方向错了整套返工不划算。用户说"不用确认直接做"就跳过这一步。

**首次在新环境运行**(比如 skill 刚装到新机器):先确认渲染依赖就绪——Playwright 已 `npm i`、chromium 已 `npx playwright install chromium`、字体在 `assets/fonts/`;缺了先装再渲(详见 `production-workflow.md` 的环境自检)。

读 `production-workflow.md` 搭建任务目录,复制 `assets/base.css`、`assets/fonts/` 和对应的 `assets/template-<style>.html`,再按 `layout-recipes.md` 中的配方填充封面和内容页版式,跑 Playwright 渲染脚本生成图片。

### 6. 图上文案去 AI 味

读 `copywriting-rules.md`,对图上的标题、要点、互动引导等文案逐一过一遍内置去 AI 味规则;如果效果仍不自然,可联动 humanizer-zh 做进一步人味改写。

### 7. 截图导出 & QA

按 `production-workflow.md` 完成截图导出,核对输出尺寸是否为 3:4;然后用 `qa-checklist.md` 做版面检查(对齐、留白、字号层级)和流量视角检查(钩子是否够强、完读路径是否顺畅);再过一遍 `diagnose-and-risk.md` 的**风控自查清单**(违禁/极限词、导流外链、搬运侵权、敏感领域),被限流一次这篇基本就废了;最后跑根目录的 `validate-cards.mjs` 做自动校验。

### 8. 交付

输出最终展示图后,**不要止于图**。按 `caption-and-comments.md` 产出配套的下半场:

- **发布正文**:前 3 行钩子 + 价值主体 + 关键词自然嵌入 + 结尾互动 CTA,整段过一遍去 AI 味。
- **关键词与话题标签**:大词/精准词/长尾词分层布局,话题 5-8 个按配比给。
- **评论区预埋**:给出可直接发的置顶评论(自问自答/钩子/争议化解/追更扣子)。

再按 `account-persona.md` 附上**涨粉建议**:这套图文给"关注"的理由是什么、可延伸成什么系列、建议的发布时间窗口。

发布后,提示用户可按 `diagnose-and-risk.md` 的**数据复盘对照表**找病因迭代(曝光低=选题/标签、点击低=封面、完读低=节奏、互动低=钩子、不涨粉=人设),一次只改一个变量。

**交付后改稿**:用户提"第 3 页改成…/换个封面标题/这套换个风格"时,直接在已有的任务目录 `index.html` 上改对应 `.poster`,**只重渲受影响的那几页**(或单张),不必整套重来。

## 复盘模式（分析已发布的笔记）

上面的 8 步是**生产模式**（给素材 → 出图）。当用户拿着一篇**已发布**的笔记来问"为什么没爆 / 帮我看看数据 / 怎么改进",进入**复盘模式**,按下面走。详细方法见 `diagnose-and-risk.md`。

### 1. 一次性收齐输入

平台没有开放接口,**读不了用户的后台,只能靠用户提供**。把缺的一次性列清楚问,别挤牙膏:

- **必需 · 后台数据**:截图发来最省事(直接读图),或文字报数。请带全这些指标——**曝光量、点击率(封面打开率)、完读率 / 人均阅读时长、互动(赞 / 藏 / 评 / 转)、新增关注**。
- **强烈建议 · 笔记本身**:封面图 + 内容页截图(至少封面)。没有它,诊断只能给通用建议,给不出"你这张封面问题在哪"。
- **可选 · 背景**:选题、标题、话题标签、发布时间。

### 2. 定位漏斗瓶颈

按 `diagnose-and-risk.md` 的诊断对照表,从数据看**哪一层最低**(不是看总量,是看哪一层在漏人),先给结论:瓶颈在曝光 / 点击 / 完读 / 互动 / 涨粉 的哪一层。曝光异常低时,先排查 `diagnose-and-risk.md` 的风控清单,确认不是被限流。

### 3. 结合实际内容给具体病因

拿用户的封面 / 内容,对照那一层的常见病因,指出**具体**问题("标题 18 个字一行读不完""第 3 页四个点挤一页""结尾只有谢谢观看没有互动钩子"),不要停在通用建议。

### 4. 给改法，可选重做

给下一版的具体改法;用户需要的话,直接用**生产模式**把改进版重做出来(最常见是先单独重做封面——点击率是最高频的瓶颈)。

### 复盘原则

- **一次只改一个变量**,否则数据变了也不知道是谁的功劳,学不到可复制经验。
- **单篇样本小**,偶然性大;攒 3-5 篇一起看趋势更准。
- **数据都好却不涨粉** = 人设 / 系列问题,不是单篇问题,转 `account-persona.md`。

## 非协商项(硬约束)

- 不杜撰具体数字、价格、引用或亲身经历。事实类内容必须来自用户素材或经核实的可靠来源;观点/方法论可基于常识原创,但关键主张需与用户对齐,不自行编造立场
- **时效/新闻/产品发布/价格/政策/数据类内容,先联网核实不确定的事实,并在最终回复里标注来源;核实不了就向用户求证,不靠记忆硬写**(记忆有截止日期,这类内容最易过时出错)
- **时间一律按北京时间(UTC+8)表述**:受众在中国,涉及"今天 / 同一天 / 差几天 / 几点发布"等时间事实,必须先把来源时间(常为美东/UTC)换算成北京时间再判断和书写。海外深夜的事件在北京往往已是次日,别把海外时区的相对关系直接搬给中国读者(典型坑:海外"前后两天"的事,换算到北京其实是同一天)
- **不杜撰账号名、@handle、二维码或任何联系方式**。图上底栏、正文、评论区的署名只能用**用户提供的真实账号**;用户没给就**留空、或只用被推广对象自己的品牌名**,绝不随手编一个 @账号——它可能正好是别人的真实账号,等于把流量导给陌生人(导流风险见 `diagnose-and-risk.md`)
- 不在图上放使用说明、快捷键提示或水印
- **`.poster` 里只放读者会看到的最终文案**:策划笔记、选题/角度的内部说明("这套图文主线不是…而是…")、互动策略说明("评论区问题:…想提高互动…")、来源核对/数据出处脚注("数据据…综述")、对内部文件的引用("见 POST_TEXT.md")等写给创作者/运营自己看的元信息,**绝不能出现在画面里**——这类内容属于第 8 步的发布正文/评论区,是独立的文字交付物,不写进 `.poster` 的任何元素
- 不静默修改用户的其他 Skill 或项目文件
- 3:4 画布必须吃满,内容占比不低于画布高度的 75%,不能出现大片空白
- 同一套图文内不混用两套风格,除非用户明确要求混搭
- 标题和封面文案不踩平台限流红线(如绝对化用语、医疗/金融违规话术等)
